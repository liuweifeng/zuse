# Staging startup latency investigation — 2026-10-11

## Acceptance boundary

Time starts at the client's workspace/message request. The pre-Git target includes allocation or wake, runtime startup, workspace authentication, and usable credentials for the selected agent: Boxd <5 s; Boat ideally 20 s, maximum 25 s; E2B between them. Git updates follow with visible progress. Report agent acceptance separately from intent persistence and from the first response. Never count a credentials-ready marker as evidence while grant acquisition is still pending.

Refresh tokens remain with the account authority. Workspace grants are access-only and bound to the workspace, runtime generation, and recipient key. Preserved-memory wake should keep the runtime, session, and credential cache alive. Cold recovery must preserve existing workspace data.

### Snapshot and control-connection experiments

The E2B image builder runs user build steps as `zuse`, then a root-only memory preparation step. It clears reusable pages, leaves 1 GiB headroom, and reads Node, the signed bundle, and compile-cache files. It retains no Node process or workspace credentials in the snapshot. A first image attempt failed because the unprivileged user could not elevate; the outer build wrapper now owns the root-only step, and a live rebuilt image passed authenticated startup.

Disposable Boxd probes found allocation around 1.3 s before memory preparation and 0.58 s after it, but import rose from 0.924 s to 1.213 s even after re-importing before capture. This is a small single-sample net improvement, not enough to justify enabling the E2B preparation on Boxd yet. Probe machines and snapshots were removed.

The control cache shares bounded E2B guest connections across API adapter instances, scoped by API origin and credential (64 credentials, 256 sandboxes each). A guest HTTP 401/403 discards the stale connection, fetches current details, and retries once. Transport failures and arbitrary process failures are not replayed. Tests cover reuse, credential isolation, rotation, and no unsafe retry: 168 provider/cache tests, provider types, and changed-file Biome passed.

### Why retained processes do not require keeping RAM allocated

Boxd distinguishes standby (RAM resident) from hibernation (memory saved to disk); both preserve processes. The adapter already uses hibernation and resumes the existing runtime. Boxd documents roughly 85 ms hibernation wake, while standby continues to bill resident RAM. Switching all paused workspaces to standby would address only a small provider-resume portion of the measured multi-second path and change idle cost, so this investigation keeps the existing policy and removes control-plane/runtime work instead. Sources: [Boxd lifecycle example](https://boxd.sh/blog/agentic-saas/) and [current pricing](https://boxd.sh/pricing/). Provider claims are distinct from the end-to-end Zuse measurements above.

## Bootstrap grant and cancellation change (23:48 UTC)

New runtimes advertise `launch-grant-v1`. After enrollment succeeds, the API may return the selected agent's sealed grant in the bootstrap response, using the existing authority and validation. Issuance is bounded to 1.5 s; older runtimes and cold recovery without a launch intent keep the previous path. The runtime seeds its existing access-only cache before starting authentication. An absent grant reuses a deterministic request ID once, including after a timed-out issuance; a rejected seed or a later refresh uses a fresh ID. This preserves the authority's idempotent refresh and avoids replaying expired cached grants.

E2B process requests now own a scoped HTTP abort signal. A caller that stops waiting closes its stream immediately, including while waiting for headers or process completion; it does not assume the remote operation stopped. This matters for the new bounded bootstrap request and keeps abandoned HTTP streams from occupying Worker connections.

Validation before rollout: 95 server auth/runtime/wake tests, 31 API grant/authority tests, two shared request-ID tests, and 43 E2B provider tests passed. API, server, contracts, utils, and sandbox-provider type checks and changed-file Biome passed. The new E2B tests interrupt requests both before headers and while reading a live process stream.
