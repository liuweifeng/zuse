# Staging startup latency investigation — 2026-10-11

## Acceptance boundary

Time starts at the client's workspace/message request. The pre-Git target includes allocation or wake, runtime startup, workspace authentication, and usable credentials for the selected agent: Boxd <5 s; Boat ideally 20 s, maximum 25 s; E2B between them. Git updates follow with visible progress. Report agent acceptance separately from intent persistence and from the first response. Never count a credentials-ready marker as evidence while grant acquisition is still pending.

Refresh tokens remain with the account authority. Workspace grants are access-only and bound to the workspace, runtime generation, and recipient key. Preserved-memory wake should keep the runtime, session, and credential cache alive. Cold recovery must preserve existing workspace data.

### Harness correction: model acceptance is not successful work

The initial harness pinned `gpt-5.4`. Reading the actual session error established that Codex rejects that model for this ChatGPT account. The timing entries above remain observations of `agent.turn-accepted`, but **do not establish a successful agent response**. The harness now sends the catalog default `gpt-6-astra` (the create schema requires an explicit model) and checks the public message stream for `STARTUP_PROBE_OK` or a terminal error. Successful-response baselines must be collected with this corrected harness. A temporary staging API key was created solely for these checks and must be revoked after verification.
