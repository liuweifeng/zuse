Good context is specific, current, and scoped to the active environment.

## Mention a file

Type `@` and search for a project file. Selecting it inserts a file chip whose path is rooted in the active checkout. In a worktree chat, search and resolution use that worktree rather than the main checkout.

Mention the smallest set of files that establishes the problem. The agent can discover related code using its tools; attaching an entire repository as prose usually makes the request less precise.

## Images, PDFs, and other files

Add files with **Attach files** in the composer's **+** menu, by drag-and-drop, or by paste. Images show a preview; other files, such as PDFs, are attached as file references. A single message can carry up to 20 attachments. Attachments are saved under `.context/files/` in the active checkout and displayed in the timeline. Zuse adds `.context` to the repository's `.gitignore` when you add a project, so attachments stay out of commits. Provider support for consuming a particular attachment type can vary by model.

For a visual bug, include the screenshot and describe the expected state. For a specification, identify the exact pages or requirements that govern the task.

## Pull context from another session

When you open a new session tab in a chat that already has other sessions, an **Add context** tray appears above the empty composer. Choose **Transcript** to attach another session's conversation, or **Plan** to attach its latest proposed plan. Zuse writes the text to `.context/files/` and adds it to the composer as a file chip. The tray disappears once the new session has a message.

## Start from an issue

On a new chat, **Create from…** can start from a GitHub issue as well as a pull request or branch. Zuse attaches the issue as a Markdown file and prefills the prompt.

## Browser and editor annotations

Annotations add precise references to the composer:

- In the editor or a diff, select code and choose **Annotate**, or press `⌘⇧A` (`Ctrl+Shift+A` on Linux), to pin a comment on those lines.
- In the integrated browser, use **Annotate page** to mark an element on the page.

Pending annotations appear in an **Annotations** tray above the composer, where you can open, edit, or remove them before sending. Review them before sending so the target is unambiguous.

## Queue a follow-up

If a turn is already running, the next message waits in the per-session queue. Queued messages preserve their submission mode. From a queued message you can:

- **Steer** the agent to it next;
- **Send now**;
- edit it, move it up or down, or remove it.

If the last turn fails, the queue is held until you choose **Resume**. Use the queue for a genuine next instruction; interrupt the current turn when the new information invalidates work already underway.
