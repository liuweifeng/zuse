A good first task is small enough to review but meaningful enough to touch the real project: fix a focused bug, add one test, or explain and improve one workflow.

## 1. Open the project

Choose **New project** in the sidebar, then **Existing folder**, and select the repository. Zuse adds it to the projects panel and reads its current Git state. Opening a project does not copy or move the repository. Zuse adds `.context` to the repository's `.gitignore`, because chat attachments are stored there, and creates a starter `.zuse/settings.toml` if the repository does not have one.

## 2. Start the chat

Choose **New chat** (`⌘N`, or `Ctrl+N` on Linux). Before sending, select:

- **Provider and model** — the coding agent that will handle the first session.
- **Workspace** — **Worktree** for a fresh isolated branch, or **Local** to use the main checkout.
- **Permission mode** — how often Zuse pauses for approval.

For an implementation task, use a worktree. It keeps the task on its own branch and leaves your main checkout available for other work. For a read-only explanation, the main checkout is usually enough.

To continue existing work, use **Create from…** to start from a pull request, a branch, or a GitHub issue, or **Import chat** to continue a recent Claude Code or Codex conversation from this computer.

## 3. Give the agent a verifiable outcome

Include the problem, the expected result, and how you want it checked.

```text
The empty state in the activity panel does not update after the first item is added.
Find the cause, fix it without changing the surrounding layout, and run the focused tests.
Tell me which behavior you verified and call out any checks you could not run.
```

Use `@` to attach a relevant file. You can also attach images, PDFs, or other files when the task depends on visual or document context.

## 4. Follow the work without micromanaging it

The timeline separates reasoning, tool calls, edits, questions, and errors. You can:

- answer a question inline;
- approve or deny a requested action;
- queue a follow-up while the current turn is running;
- stop a turn that is heading in the wrong direction;
- open a changed file or terminal without leaving the chat.

Turn on Plan mode (`⇧Tab`) before sending when you want exploration and a proposed implementation before any edits.

## 5. Review the result

Open **Changes** and read the diff. Select only the files that belong in the commit, run the relevant checks in **Terminal**, and send corrections in the same chat if needed.

When the branch is ready, use the action in the top bar to commit and push, create a pull request, fix failing checks, resolve conflicts, mark a draft ready, or merge. The available action changes with the actual Git and pull-request state.

## What persists

The project, chat, session timeline, tool results, and worktree association remain available after an app restart. A provider process may have to resume or restart, but Zuse keeps the durable local history as the record of what happened.
