Zuse treats a mobile network interruption as recoverable state. The app retains its last downloaded projects, chats, sessions, and messages, then reconciles them with the environment when the connection returns.

## What remains available

- The most recent downloaded inbox and session list.
- Cached conversation messages and timeline state.
- Messages you composed while offline, saved per session.
- Connection records needed to retry the environment.

Live agent output, new project reads, file browsing, approvals, and execution require an online environment.

## Sending while offline

When a session is offline, the composer saves your message on the phone instead of sending it. You can still edit or cancel it until the connection returns. After reconnection, Zuse hands each saved message to the app's durable send queue exactly once, in order, with a stable ID so a retry cannot create a duplicate.

If delivery fails, the message is marked **Not delivered** with **Resend** and **Remove** actions. Avoid duplicating it manually unless you have confirmed the server did not accept the original.

## App backgrounding

When iOS backgrounds Zuse, the active transport is treated as offline. Cached screens remain available, and the connection supervisor reconnects when the app becomes active again. A brief **Connecting** or **Reconnecting** state after returning is expected.

## Notifications

Zuse can alert the phone when an agent needs your attention. Notifications require a signed-in account:

1. Open **Settings**, choose **Sign in**, then **Sign in for remote access**.
2. Return to **Settings** and turn on **Notifications**.
3. Allow the iOS permission.

Opening a notification takes you to the inbox. To turn alerts off, or if you denied the permission earlier, change notifications for Zuse in iPhone Settings. Notifications are an attention aid, not the source of truth; pending prompts also appear inside the relevant session.

## Storage controls

Open **Settings → Storage** to see how much space Zuse uses.

**Clear downloaded data** removes cached projects, chats, and messages, then fetches them again as needed. It deliberately keeps connections and unsent messages.

**Clear media cache** removes fetched images and document previews. They download again when needed.

**Reset app** removes account state, connections, cache, device keys, and unsent messages from that phone. Your remote account and environment data remain unless you separately choose **Delete account** under **Settings → Account**.

<SecurityNote title="Lock-screen privacy">
Use iOS notification-preview controls if approval or question text should not appear on the lock screen. Treat a remotely connected phone as an authenticated workspace client.
</SecurityNote>
