Serve separates service lifecycle, account registration, runtime installation, and workspace data. Choose the narrowest command for the outcome you want.

## Check health

```sh
zuse serve status
```

The readable report shows the computer name, service state, tunnel configuration, detected agents, reachability, and hosted app URL. For scripts and diagnostics, use the [versioned JSON form](/serve/status-json/).

## Start or reinstall

```sh
zuse serve start
```

`start` is also the default action. It creates the private data directory, saves the start options, obtains account authorization when needed, installs the current runtime into the managed runtime directory with npm, and installs or refreshes the user service. It waits up to 45 seconds for local reachability before reporting success.

Each `start` replaces the saved options with the ones you pass, so repeat any access options you want to keep. `status`, `stop`, `update`, `logout`, and `uninstall` reuse the saved options.

For a temporary foreground process:

```sh
zuse serve start --foreground
```

Foreground mode runs in the current terminal. Closing that terminal stops the environment.

## Choose how clients connect

By default, `start` signs in to your account and creates a managed HTTPS tunnel, so the computer appears in other signed-in Zuse clients. The server listens only on `127.0.0.1:4859`. Add options to `start` for other routes:

| Option | Effect |
| --- | --- |
| `--tailscale` | Also share the computer privately over Tailscale Serve HTTPS. Serve prints the **Tailnet** address. |
| `--lan` | Listen on the local network (`0.0.0.0`). Traffic uses plaintext HTTP; authentication is still required. |
| `--host <addr>` | Listen on one specific address instead of `127.0.0.1`. You cannot combine it with `--lan`. |
| `--port <n>` | Listen on another port, from 1 to 65535. |
| `--no-account` | Skip account sign-in and the managed tunnel. The computer does not appear in your account. |

```sh
zuse serve start --tailscale
zuse serve start --lan --port 5000
```

If Tailscale is not ready when the service starts, the service keeps running without the tailnet address and checks again every 30 seconds. When Tailscale becomes ready within 10 minutes, the service restarts once to add the address; after that, it logs a reminder to run `zuse serve start` again with `--tailscale`.

`--ssh-managed` runs a loopback-only host without account linking for SSH tunnels. It installs a separate user service, so it does not replace your regular Serve service, and it cannot be combined with `--tailscale`, `--lan`, or `--host`.

## Stop

```sh
zuse serve stop
```

This stops and disables the background service. It does not revoke the account link or delete the runtime, database, logs, or workspaces.

## Update

Serve requires an explicit safe-work confirmation:

```sh
zuse serve update --force
```

Before running it, stop or finish active agents and terminals. Serve resolves the latest `@zusehq/serve` version from the npm registry, installs it into a versioned runtime directory, reinstalls the service with your saved start options, and waits for a reachability check. If the new runtime cannot become ready and a previous runtime exists, Serve restores the previous service definition and reports the rollback.

There is intentionally no unattended update command in this release; `--force` acknowledges that active-work readiness checks are still your responsibility.

## Sign out this computer

```sh
zuse serve logout
```

Logout revokes the environment registration, stops the service, and clears the saved Serve account session. If this computer was never linked, there is nothing to revoke and Serve only stops the service and clears the session. Repositories and workspaces remain on disk. Run `zuse serve start` and authorize again to relink the computer.

## Uninstall the managed runtime

```sh
zuse serve uninstall
```

Uninstall removes the user service definition and the managed `runtime` directory. It preserves workspaces and the rest of the Zuse data directory. If you also need to revoke the hosted registration, run `logout` before uninstalling.

<Warning title="Update during a quiet window">
`update --force` can restart the service. Do not run it while an agent or terminal has important active work.
</Warning>
