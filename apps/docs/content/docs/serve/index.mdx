Zuse Serve turns a Mac or Linux computer into an environment you can open from the hosted web app or Zuse for iPhone. The computer owns its repositories, provider CLIs, credentials, terminals, and session state. Your account supplies identity and environment discovery.

## Requirements

- macOS, or Linux with a systemd user session for durable background operation.
- Node.js 22.13.0 or newer and npm. Serve installs its managed runtime with npm.
- At least one supported agent CLI installed and authenticated.
- A browser on any device to complete account authorization.

## Quickstart

Run the installless command on the computer that will host the work:

<Command>npx @zusehq/serve</Command>

Zuse prints an authorization code and opens the verification page when possible. Complete sign-in, then wait for **Zuse Serve is ready**. The final summary includes the computer name, online state, account, detected agents, tunnel address, and hosted app URL. When browser pairing is available, it also prints a **Browser** link and a short pairing **Code**; the first visit from a new browser asks for that code.

Open the hosted app with the same account and select the computer. On iPhone, sign in under **Settings → Remote access**; online Serve environments appear alongside other linked computers.

## Installed command

The package publishes the `zuse` executable. If you install it globally, the canonical command is:

<Command>zuse serve</Command>

Running `zuse serve` with no action is equivalent to `zuse serve start`. The `zusehq` package (`npx zusehq`) runs the same CLI.

## Durable background service

On macOS, Serve installs a user LaunchAgent. On Linux, it installs a systemd user service. By default, the service starts the protected server on loopback (`127.0.0.1:4859`), links it to your account and its managed HTTPS tunnel, and keeps its runtime and logs under the Zuse data directory. To add Tailscale or local-network access, see [access options](/serve/operations/#choose-how-clients-connect).

If the current platform does not provide a supported service manager, such as a Linux session without systemd user services, `start` fails and explains why. Run `zuse serve start --foreground` for a temporary session in the current terminal, and keep that terminal open.

## What Serve does not do

Serve does not install provider CLIs, clone repositories, or provision a cloud computer. Prepare the machine and its workspaces first. Direct SSH launching and automatic machine provisioning are not part of this public workflow.
